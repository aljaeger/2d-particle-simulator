# 2D Particle Simulator

The goal of this project is to produce a 2 dimensional particle simulator for charged particles in python. The idea is that we have draggable elements that we can place. I would like to separate the project into stages, separating the simulation itself from the visual interface. We will define a ParticleSimulator2D python class. This class contains the different types of elements we wish to add, each of which should be their own python class that are appended to the particle simulator object in an array elements. Within its class we only put its parameters. simulation will be a part of the simulator.
- Wall, defined by its 2 opposing corners. Its purpose is to absorb particles. No other parameters are required.
- Magnetic field; defined by opposing corners of the rectangle, and Bz. 
- Electric Field; defined by opposing corners of the rectangle, and Ex and Ey.
- Detector; defined by opposing corners.
beyond that, each element should have a function interact() which is passed current particle position and momentum, and returns: the acceleration on the particle, whether the particle is killed, and whether the element detects the particle. This will be used in the integration loop of the particle. The detecting particles should set an internal state detecting to true or false; this will be used for visualization.

In the simulate function, we initialize with a particle source with initial momentum distribution, defined by a position x,y, mean Px Py and variance sigma_Px, sigma_Py. We define a simulate() function which samples an initial particle, and integrates it in time. This will require a loop over time steps, so the simulate function needs default arguments for simulation time T and number of time steps that can be configured. Inside the loop, we call a simulate() function, which determines the force on the particle by summing over all interactions of its elements, determines whether it is killed by taking .any() over the boolean array of whether any elements kill the particle, and returns the corresponding state after the step: a boolean for whether the particle lives, the updated position and momentum, and a dict with detector ids and outputs. This requires the detector objects to have an id variable which is chosen by the user upon initialization. The simulate() function itself should return a particle track, and any detection events which occurred as time, detector, duration pairs. contiguous detection events should be grouped into a single event by its duration. 

The ParticleSimulator2D object should have a .addelement() member function by which elements are added, passed as their corresponding object.  we need to deal with different element types. I think the cleanest is if we require a general architecture that gives every element the same interface, but the other elements like magnetic fields just dont have detection outputs (always false) and killed (always false) whereas one of them is set to true for walls or detectors. It may make sense to define a super class which is inherited from called Element which defines all their common member functions. Please make a clean architecture: Elements are stored in one directory, the simulator is stored in the root directory, etc.

For visualization, I want a particle track to be black, wall to be black, detector to be seethough grey or green depending on its state, magnetic fields seethrough red with crosses or dots indicating direction into or out of the page, electric fields seethrough blue with arrows indicating their direction. ensure arrows are normalized so it doesnt look weird. Create a demo script in which particles are created in the bottom left and shot sideways, and are steered by magnetic fields in the corners, include the animate output and .savefig output.
